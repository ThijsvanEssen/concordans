Conventions:

- The URL holds the state a link should keep.
- Components call the API through `$lib/api` and never call `fetch`.
- Every page loads as lazily as it can:
  - The first paint waits only for the cheapest call that gives the head and the main text: a person's reader on `/api/members/{id}`, a judgment on its text, not on the node.
  - Everything else follows in parallel, each part with its own "laden…": Verbonden, the network, counts, lists, votes, facets. Where it can, a part loads when it comes into view or is opened.
  - A slow or failed part never holds up or empties the rest; it says so in its own place.
  - A call the API may take long for (search lanes, the feed, a full node, a person's votes) waits as long as the API does (`slowApi`, 30 s), not the 10 s of `api`.
  - A new or changed page is checked for what is on its critical path: which calls the first paint waits for, and whether each must.
- A click on a bron in the network marks it; it does not open it:
  - One click (a tap on a phone) lights the bron and its own lines, with its card beside it: Tekst lezen, Toon verbonden bronnen, In het netwerk. The network keeps its size.
  - The reader opens with Tekst lezen, a second click on the bron (a double click too) or Enter.
  - A click on the empty network or Escape removes the mark. Toon verbonden bronnen shows the bron's own neighbourhood in place of the netwerk.
- On a phone, whatever puts a bron in the network or opens it there goes to the Netwerk tab: In het netwerk, toon in netwerk, a row of Verbonden, and a link to the network from Bladeren or Actueel (`bronHref(…, { mode: 'graph' })` carries `paneel=netwerk`, read once). What it did stands at the foot of the network, with Ongedaan maken (`meldNetwerk`).
- A bron's place (what it belongs to, what stands beside it, what falls under it) follows [`hierarchie.md`](hierarchie.md), in the source's terms; the band "Behoort bij" and the groupings of the network read it from there.
- Every list with dates has the same period filter: `Periode.svelte` in `src/lib/components/ui`, first in every filter pane: Alles, Maand, Kwartaal, Jaar (back from today) or Eigen as one segmented row over the full width of the column (Keuze `vol`), and van and tot as day fields only under Eigen, aligned with the row (one line where both fit, else under each other). The search has the same component. The bounds are days (YYYY-MM-DD) in the URL and to the API. Verbonden and the network have it in the filter sheet. Actueel and Bladeren follow [`bediening.md`](bediening.md); Bladeren takes the `range` group out of its facets into its choose-line. Actueel has the page's field and Periode on one line above the list, the facets with their counts on the left (Kamer, Soort, Ingediend door, Stemde with its Stem voor or tegen, Ministerie, then the rest), a chosen option in bold where it is chosen and no chips; on a phone the filters behind Filter (N); the actions (Volg, Volg als onderwerp) beside the heading. The other filter panes follow the same pattern. A list whose route has no period yet waits for the back end; a list whose dates are its own rows (the kabinetten) filters them itself. Onderwerpen excepted: a signal page with its own window (30 days, or since the visit before); the lists it leads to have the period (the Overzicht, Actueel).
- The interface explains itself. No paragraph of explanation above or under a panel, a list or a form: what a user needs to know follows from the controls, their labels, a placeholder with an example ("AI; kunstmatige intelligentie"), a marker on a row ("nieuw"), the period in the filter. A title (tooltip) only where a control is unclear without it. A status line that says how far the data or a search reaches ("tot en met 8 okt.", "Doorzocht vanaf …") is data, not explanation. The documentation (`/docs`, `/privacy`) keeps its explanation: that browser storage stays in the browser is said there, not beside the control.
- The plenaire zaal is drawn as the Kamers draw it themselves. The Tweede Kamer as on its "Zetelverdeling plenaire zaal" (https://www.tweedekamer.nl/kamerleden-en-commissies/wie-zit-waar): seen from the public tribune, the front at the top (1 Voorzitter, 2 Griffier, 3 Kabinet (vak-K), 4 Verslag en Redactie, 5 Spreekgestoelte, 6 Interruptiemicrofoons, 7 Bodedienst, the Kamer's own numbers), the rows in six blocks below it, the fracties from the Voorzitter's left (`order`) starting on the right of the picture (`Hemicycle.svelte`). The Eerste Kamer as on https://www.eerstekamer.nl/wie_zit_waar: two blocks facing each other, the regering at the top, the Voorzitter at the bottom (`ZaalTegenover.svelte`). A mark per fractie (coalitie and oppositie, voor and tegen) is a seat in the fractie's colour against an open one, never colour alone. The majority (76 of 150, 38 of 75) is a line in the course of a cabinet's seats, at its true height on the Kamer's whole scale (`KamerZetels.svelte`).
- Comments say why, not what.
- The interface is Dutch; code and these files are English. The interface calls a node a bron and an edge a verbinding.
- A name in the code is English, in the words of the API (`member`, `faction`, `judgment`, `decision`, `chamber`), save the closed list of Dutch legal terms in `TERMS` of `src/lib/guards/naming.test.ts` (bron, verbinding, lid of an article, overweging, dictum, grondslag, peildatum, hamerstuk, kamerstuk, strekking, toezegging). Texts on the screen and URL parameters stay Dutch. One word has one meaning: `kind` is the API field, the three views are `read`, `graph` and `index` (the route `explore`). The guard counts the names with another Dutch word; that count only goes down, so a module that is touched moves to English.
- Styles take their sizes from the tokens in `src/lib/styles/tokens.css` (`--t-*` for type, `--s-1` to `--s-8` for space). `src/lib/style-scale.test.ts` fails on a font size in pixels and on more pixel values in spacing than `PX_IN_SPACING_MAX`; a rule that is changed moves to the tokens, and `PX_IN_SPACING_MAX` goes down to the new count.
- The tokens follow the Design System (`docs/claude/design-system/tokens.json` in lawgraph): same names, same values. The favicon, the app icons and `static/og/*.png` are made from them by `node scripts/deelafbeeldingen.mjs`.
- A rule that holds across the code (one form, one place, one name) is a guard in `src/lib/guards/`, one file per theme; a new guard is a new file. Guards read the sources through `src/lib/test/bronnen.ts` (and `TESTS`, the test files, where a guard asks who uses a name): `bron(path)` fails on a missing file, `overtreders` and `regelOvertreders` give the files or lines that break a rule, and an exception is an `Uitzondering` with its reason that fails the guard once it excepts nothing.
- Nothing stays that nothing uses (`src/lib/guards/opruim.test.ts`): every prop of a component has a caller that gives it, every export another file that names it (an export only a test names is one its own module uses too), and a name has one address: no re-export, an import goes to the module that defines the name.
- A module's tests stand beside it in one file of the same name (`rows.ts`, `rows.test.ts`; a component in a page `Name.dom.test.ts`, runes that react `name.svelte.test.ts`); a test over several modules is named for the behaviour it holds (`lezen-ter-plekke.test.ts`). Tests use `describe` and `it`, and their names are English, with the Dutch terms of the sources and the interface as they are.
- What a reader does in the browser is tested by the browser suite in `e2e/` (Playwright, the README of the repository): every kind of page, the journeys and the behaviour across pages, against the production build with the API from recorded fixtures.
