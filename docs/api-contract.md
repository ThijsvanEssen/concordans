# API contract

The schema of the API is the contract.

| File                                     | Written by         | Read by                                       |
| ---------------------------------------- | ------------------ | --------------------------------------------- |
| `src/lib/api/openapi.json`               | `npm run sync:api` | the `/api` page and the type generator        |
| `src/lib/api/generated/openapi-types.ts` | `npm run sync:api` | the compiler, through `api` and `Schema<...>` |

`npm run sync:api` fetches the schema from the API in `.env` (`PUBLIC_CONCORDANS_API_BASE_URL`) and regenerates the types. Neither file is edited by hand. The version is `info.version` in `openapi.json`.

`npm run check:api` runs `sync:api` and fails when either file differs from what is committed. A change of the API then shows as a diff and, where a call or field is gone, as a compile error in `npm run check`.

The schema types the names of collections and relations as enums; `src/lib/vocabulary.ts` takes `Collection` and `Relation` from it, and its tables are records over them, so a name the API adds or drops fails the check. Which collections each relation joins is `src/lib/api/relations.json`, the same file as lawgraph's `tests/data/relations.json` (generated by `python -m lawgraph.core.relations`); the tests of Verbonden's groups and words read it. The schema types node `props` as a plain object: views read props by name (`slug`, `number`, `ecli`, `bwb_id`, …); check a prop against the API before relying on it.

A dossier is addressed by its number with suffix (`37020-XV`, which is not `37020`). Every dossier field of the API and every route carries that number. The node key differs from it where there is a suffix (`36600_viii`); a dossier node has the number in `props.label`.
